# 正向局部事实与覆盖检查：开始确认未使用，仍未通过全部验收

按“模型判断局部事实，程序负责覆盖与整体结论”改造后，同一批已知案例中，未使用的确定结论从上一轮的 0/30 提升到 10/30。58 次确定答案全部符合预先标签，错误删除建议为零。但运行使用的确定结论减少，待审查率仍为 51.67%，因此继续保留实验分支，默认仍使用 LLM。

## 当前代码的判断方式

- 程序枚举本地文件，对支持的 JS/TS/JSX/TSX 与 JSON 完整读取和解析。所有检查文件都参与局部判断，包括没有依赖名的文件。包清单的依赖声明剔除，其他字段保留。覆盖记录包含检查文件、排除目录与具体缺口。
- Jev 对每条完整文件分别回答三个正向 Noul 问题：是否存在运行使用、是否存在工具链使用、是否存在尚未查清的潜在消费者。最终请求的公共状态只含依赖与包身份，不重复整份台账，也不询问“整个项目是否未使用”。
- 运行与工具链使用可以同时存在。存在任意可靠使用证据即可支持保留；确认使用及支持记录仍要求分数至少 0.90。
- 程序计算 `localNonUseScore = 1 - max(runtime_usage, tooling_usage, unresolved_consumer)`。只有覆盖完整、重要调查缺口已关闭、每个完整文件的三个原始分数均不超过 0.10，才允许确认审查范围内未使用。直接引用和既有业务/融合保护仍有效。
- 原始三个 Noul 分数与派生分数分别保留。聚合使用取最高值，聚合非使用取所有完整文件的最低派生值；这些聚合值和五类融合权重不是模型的全局概率，更不是已校准正确率。

覆盖范围是有边界的：排除 vendor、生成目录及静态资源；文档仍是声明。未知格式、读取/解析失败、符号链接和检查超限会阻止非使用结论。环境/私钥文件只记录缺口，不读取内容。初始上限为 2,000 个目录项、32 个文件、单文件 64 KB、累计 128 KB；monorepo 跨包消费者尚未验证时保持待审查。大型真实项目及跨文件消费者解析仍可能导致大量待审查。结论不覆盖外部部署、生成文件或第三方代码，删除仍需人工核验。

40 个原有案例、每例每种提供方预热一次并正式测量三次，共 240 次正式审查。状态 `completed`，无缺失行或 API 错误。每次使用独立临时项目，关闭记忆和遥测写入；模型请求超时 10 秒，零重试，调查上限六轮。案例标签和验收标准未修改。

62 次待审查中，30 次本来就应待审查，32 次属于额外弃答。因此理想分类下的待审查率仍为 25%，本轮高出 26.67 个百分点。原始记录均以 `low-confidence` 标记未通过派生判断门槛；未知消费者的原始分数可用于区分潜在缺口和使用方式不确定。

收益和代价同时存在：未使用召回从 0 提升到 33.33%，工具链从 v2 的 28/30 提升到 30/30；运行使用则从 v2 的 27/30 降到 18/30。减少公共上下文与问题变化同时发生，无法把这些变化全部归因于单一因素，也不能视为全面改善。

例如 `unused-1` 三次都通过覆盖与局部门槛，正确确认未使用。`unused-2` 的“未来可能集成”注释，三次未知消费者分数都为 0.12，高于 0.10，因此保持待审查。`runtime-6` 的已加载库导出写法，运行使用分数约 0.71–0.77，也未达到 0.90。后续应在新标注案例上研究局部问题表述和阈值校准，不针对这批已知材料继续降低门槛。

## 换序、验收与局限

另选六例正常/反转问题及动作选项顺序，最终类别全部一致。三例两次均给出确定结论：工具链两例、未使用一例；其余三例两次均待审查。抽样一致不能证明全部案例稳定，也未隔离随机变化与顺序影响。

完整测量、零错误删除、F1 不低于 LLM、p50 至少减半、p95 不恶化及换序抽样均通过。**待审查增加不超过 5 个百分点未通过**：51.67% 对 28.33%，增加 23.33 个百分点。`passes: false`，没有更改标准使其通过，没有提升为默认功能。

这是同一批 40 个已知合成案例各重复三次的系统级回归，不是 120 个独立案例或新的留出验证。Jev 额外读取完整本地文件，LLM 沿用原台账路径；两者上下文不同。错误删除只统计建议，没有实际删除。这里支持继续验证局部事实与覆盖设计，不能证明 Jev 普遍优于 LLM或证明 Harness 是全部失败的唯一原因。
