# Jev v10：局部加载关系与内联脚本

本轮有局部改善，但新验证集没有达标。全新 20 例三轮正确 52/60，37 个确定结论全部正确，仍有八次额外待审查；宏平均 F1 为 0.8696、待审查率 38.33%，六例换序检查有一例结果不同。不能据此宣布 Jev 已达到替代标准。只调用 Jev，默认提供方仍为 LLM，分支只保留本地。

## 实现与控制

`review-local-context.ts` 给模型补充可核查的局部语法关系：不可变字符串绑定、别名、字符串拼接和即时字面量数组 join；列出加载表达式、参数解析结果及位置。可变绑定、未知调用、对象属性、变量数组及动态代码不伪装成已解析，不执行项目源码。目标字符串绑定附带声明、实际引用计数和引用语句；代码中导出或交给未知函数的目标名称仍交给模型判断。

package.json 仅对严格匹配的完整 `node -e/--eval` 引号命令提供内联 JS；原始清单也保留。复杂 shell、插值和无法解析的脚本保持未知。问题区分打印文本与实际加载，Node 脚本中的加载归工具链使用。支持信息有明确数量/长度边界，完整记录没有被这些摘要替换。

维持 0.90 使用门槛、0.10 局部否定门槛、完整覆盖、缺口和业务一致性检查。语法事实只补充模型输入，不直接指定判定、改写概率或放宽删除条件。SDK 模型 jev-1.13.0、六轮上限、10 秒超时、零重试和无 LLM 降级保持不变。

v9 开发集的 n02（数组 join 后 import）和 n15（Node 打印包名）三轮均已改善，但 n13/r04 仍有额外待审查。v10 增加绑定实际引用和两个外部消费反例，r04 三轮通过，n13 仍全部待审查。开发集从 12 例增至 14 例，其标准待审查比例也从 41.67% 变为 50%，不能直接比较两集的总待审查率来衡量净提升。

另做 24 请求的配对诊断：四个已知案例、三轮、两种问题措辞，其他输入保持相同。把“潜在消费者”改成更显式的目标数据流问题，n13 的未知消费者分数仍是 0.14–0.15，原措辞为 0.14–0.16，没有跨过否定门槛；新措辞没有采用。诊断只探测固定调查后的最终问题，不代替完整流程测试。

## 新集未过关的边界与下一步

- p03：已解析 `tooling-lib/adapter` 子路径加载并导出模块，运行分数 0.85–0.87，未知消费者 0.68–0.72，三轮全部待审查。当前问题尚未明确说明包子路径属于同一依赖，虽然提示已经列出实际参数。下一轮应将目标身份及子路径关系明确呈现，并补充相似名称的非目标反例。
- p11：加载 other-lib、打印目标名称，两轮未知消费者 0.11，多一次换序类别差异。显示文本与未知消费者的边界仍有门槛附近波动。
- p15：拼接 other-lib 后加载、打印旧目标名，三轮未知消费者 0.12–0.14，且一次运行分数 0.11。与已知 n13 类似，局部参数关系尚不足以让否定稳定成立。下一轮可以评估把“未解析加载参数”与“目标名称导出/外传”拆成可核查的问题；不能通过概率阈值下降或直接忽略完整文件来绕开它。

新集首次调用前冻结代码与标签，首次结果后没有修改生产实现或标签再测这批材料。以上失败现在可以成为下一轮开发数据，但不能再用作新的独立验证。独立目标中的零错误确定结论及零错误删除通过；宏 F1 >=0.95、待审查率 <=30%、六例换序稳定均未通过。继续保留实验，不提升默认、不启动 LLM 对照。

## 延迟、验证与证据
